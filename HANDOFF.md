## Stage 7 status - Quality and fixes (CameraProject-Stage-07-Quality.zip, app version 0.7.N; written, NOT compiled or tested - sandbox has no Android SDK)
Owner's Stage 6 test report (2026-10-23, Stage 6 build was green and installed): (1) camera/photo quality dropped a lot and looks glitchy - MAIN PRIORITY; (2) slow motion loses focus and records very dark; (3) with watermark ON two photos were saved (with and without) - wants ONE; (4) photos/videos must open in the Gallery or Google Photos; (5) unsure if HDR and Ultra HD work; (6) this image is the app logo (design/fovea-logo-source.png).
What was changed (no compiler, reasoned from the code):
1. Photo size: ImageCapture now always asks explicitly for the HIGHEST available resolution (ResolutionStrategy.HIGHEST_AVAILABLE_STRATEGY) in the chosen shape, instead of relying on a default. Ultra HD still uses the high-resolution switch.
2. Histogram no longer binds a third camera stream (ImageAnalysis). On many phones an extra stream makes CameraX/the camera choose a SMALLER photo size - the most likely cause of the quality drop. The histogram is now read from the preview picture (CameraEngine.sampleHistogram, called from a loop in CameraScreen every 300 ms; PreviewView.bitmap, 64x64 luma bins). Same look in the UI.
3. Saved copies (watermark/Look/effect) keep more detail: limit raised from 8 MP to 16 MP before halving, JPEG quality 95 -> 98, android:largeHeap=true in the manifest so the bigger copy has memory.
4. One photo for watermark: when watermark is ON the original is deleted after the watermarked file is saved successfully (if the copy fails the original stays). Watermark OFF = original only. Look-only and Tilt-shift/Documents still save original + copy (unchanged owner rule; ask owner if they want these single too). Burst/time-lapse still originals only.
5. After a normal photo the app now shows the real saved size, e.g. "Saved 12.2 MP (4000x3000)" (also for the watermarked file). This lets the owner verify quality and Ultra HD (Ultra HD should show a bigger number than normal if the phone offers its high-resolution mode). Burst/time-lapse do not show it (announce=false).
6. Slow motion: frame rate is now capped at 240 fps (480/960 fps are far too dark; only used if nothing lower exists). AE mode ON, auto anti-banding, exposure compensation +2 stops where the camera allows it, continuous video autofocus where available (Camera2Extras.startSlowMo). Still untested on real hardware.
7. Open in Gallery / Google Photos: new camera/MediaOpener.kt tries the phone makers' Gallery apps first (Xiaomi/Samsung/Oppo/OnePlus/vivo/Huawei/Motorola/Nothing/Google gallery3d), then Google Photos, then any app. Used by the camera thumbnail, the Recent captures list and the Review "Open"/"Play" button.
8. App logo: adaptive launcher icon from the owner's logo (res/mipmap-*/ic_launcher_foreground.png, mipmap-anydpi/ic_launcher*.xml, values/ic_colors.xml background #2B2E34; manifest icon + roundIcon). The sparkle watermark in the source image was cropped out.
9. HDR / Night / Portrait: NOT changed. They depend on the phone exposing CameraX Extensions to apps (many phones do not; the MORE sheet then shows N/A and Settings > Device capabilities says so). Ask the owner what each mode showed.
10. Preset codes moved to Stage 8, public release to Stage 9. App text updated. Version 0.7.N.
Risk to tell the owner honestly: written without a compiler. If the build is RED, ask for the lines starting with `e: file` and fix them inside this same Stage 7 ZIP. Quality fixes 1-3 are the best-reasoned guess; if photos are still soft, ask for: the "Saved X MP" number, the phone model, whether Prioritize speed is on, and a screenshot of Settings > Device capabilities.
Files changed: camera/CameraEngine.kt, camera/Camera2Extras.kt, camera/LookProcessor.kt, camera/MediaOpener.kt (new), ui/camera/CameraScreen.kt, ui/screens/Screens.kt, nav/AppNav.kt, AndroidManifest.xml, res/ (icon), app/build.gradle.kts (0.7.N), design/fovea-logo-source.png (new), HANDOFF.md, CHANGELOG.md, RELEASE_NOTES.md.

## Stage 6 status - Special modes (CameraProject-Stage-06-Modes.zip, app version 0.6.N; build GREEN, installed 2026-10-23; owner's test report is in Stage 7)
Owner's requests this stage: (a) photos/videos must save straight to the phone Gallery and open in the phone's Gallery app when "Recent captures" is tapped; (b) turn on ALL planned modes now; (c) include the fixes. Panorama is postponed.
What was built (all in code, none compiled):
1. Gallery: files were already saved with MediaStore (Pictures/Fovea, Movies/Fovea) so the Gallery sees them. Now the camera screen's recent thumbnail opens the NEWEST capture in the phone's Gallery app (ACTION_VIEW + read grant); inside Fovea's "Recent captures" list a tap also opens the Gallery app. Fovea's own Review screen is only the fallback if no app can open it.
2. Mode picker: MORE sheet (Capture tools) now lists the special modes (SpecialMode enum in state/CameraUiState.kt) with a check on the active one and "N/A" where the camera does not offer it. The PORTRAIT token on the mode row toggles Portrait blur. Picking PRO / VIDEO / PHOTO leaves the special mode. Special mode is never saved (always starts Normal). Drive mode (burst/time-lapse) works only in Normal.
3. HDR / Night / Portrait blur: CameraX Extensions (new dependency androidx.camera:camera-extensions:1.3.4). Availability is read from the real camera (DeviceCaps.extHdr/extNight/extBokeh). If the phone does not offer it, or binding fails, the app says so and goes back to the normal camera (engine.specialFailed). Histogram is switched off while an extension is active. IMPORTANT: many phones (possibly the owner's Poco X7 Pro) do not expose extensions to third-party apps, then these show N/A. That is honest, not a bug.
4. Tilt-shift and Documents: processed COPY like Looks (LookProcessor.createLookCopy(..., effect)). Tilt-shift = blur at top and bottom (shrink/enlarge blur, no extra libs), name suffix _TILT. Documents = grayscale + strong contrast + brighter paper, NO auto-crop, suffix _DOC (Look is ignored in Documents). Original always kept. Watermark still works on top.
5. Ultra HD: ImageCapture uses highest-available resolution; the CameraX high-resolution switch (setAllowedResolutionMode) is looked up by reflection so an older CameraX cannot break the build. If the phone's 50 MP mode is not exposed, the result is just the highest normal size.
6. Long exposure: NOT a real long shutter. Takes 8/16/30 photos (cycle in MORE) and averages them (camera/LongExposure.kt, ~3 MP result, JPEG, suffix _LONGEXP). Needs a steady phone/tripod. Shutter again cancels (nothing saved). Memory-safe, OOM is caught.
7. RAW / DNG: camera/Camera2Extras.kt. CameraX is released, a Camera2 session captures RAW_SENSOR with a short preview run for exposure, DngCreator writes a .dng to Pictures/Fovea, then the screen rebinds (engine.rebind). The preview pauses ~2 s. Needs DeviceCaps.rawCapable (real camera capability). UNTESTED on real hardware; some phones restrict RAW to specific physical cameras.
8. Slow motion: Camera2 constrained high-speed session + MediaRecorder (no audio, preview paused while recording, 1080p max, highest fps the camera reports, usually 120/240). Saved as an ordinary high-frame-rate MP4 (Movies/Fovea, name _SLOWMO); it is NOT retimed, so the user must use the Gallery's slow-motion/speed tool to see it slowed down. Honest message says so. Needs DeviceCaps.highSpeed. UNTESTED on real hardware.
9. Dual video: CameraX ConcurrentCamera (Android 11+ and phone support): rear preview on top, front below, two videos (FOVEA_..._BACK.mp4 with audio, ..._FRONT.mp4 without), 720p-class. If unsupported the app says so and returns to normal. UNTESTED on real hardware.
10. Capabilities screen lists RAW, slow motion, HDR, Night, Portrait, Dual. Stage numbering in app text updated (preset codes = Stage 8). Version 0.6.N. Unit tests Stage6ModesTest (view model rules, availability, effect mapping).
Risk to tell the owner honestly: this stage was written without a compiler (no Android SDK, Google Maven blocked). If the build is RED, ask for the lines starting with `e: file` and fix them in this same stage ZIP. Camera2 parts (RAW, slow motion) and dual video are the most likely to need a real-phone fix; those fixes go to Stage 7.

## Stage 4 status (done; written earlier as CameraProject-Stage-04-Stability.zip; owner installed it, no bugs reported except Play Protect warning)
Owner asked for FIXES ONLY in Stage 4 (no new features). All changes below are small and low-risk; nothing was compiled because the sandbox has no Android SDK.
1. Golden spiral guide redrawn (owner reported it looked wrong). Old code drew a floating logarithmic spiral. Now a true golden spiral fitted to the frame: pure geometry in state/GoldenSpiral.kt (frame cut at 61.8% repeatedly, one quarter-ellipse arc per piece, 10 arcs, continuous; portrait starts with top piece, landscape with left piece), drawn by ui/camera/GuideOverlay.kt. Unit tests: continuity, stays inside frame, arcs shrink, start corner.
2. Camera is released when the camera screen is left (Settings, Gallery, Presets...): CameraEngine.unbind() called from CameraScreen's DisposableEffect. Stops a running recording safely (video is finalized), saves battery, frees the camera. It rebinds on return. Capabilities are kept so the Device capabilities screen still works.
3. Interrupted video: app sent to background, low storage or size limit no longer shows a meaningless "error code N". The partly recorded video is kept, the message is human text, and recording now has a file-size limit = free space minus 30 MB so it stops cleanly before storage is full. Too-short recording says nothing was saved.
4. Camera start: a cancelled start (screen changed during first start) no longer shows a false "Camera could not start".
5. Updater: check/download now run in UpdateManager's own scope (startCheck/startDownload) so leaving Settings no longer leaves it stuck on "Checking" or "Downloading".
6. Crash guards: Open/Share/Install with no app that can handle it now show a message instead of crashing; failed delete shows a message (can happen for files from an older Fovea install).
7. Look copy: a failed JPEG write or out-of-memory removes the half-written file; no crash if the app is closing while a look is processing.
8. Saved gridline opacity/thickness are clamped when loaded (corrupt value cannot break drawing).
9. Accessibility: shutter and recent-capture buttons have spoken descriptions (Take photo / Start recording / Stop recording / Open recent captures); top tokens, mode tokens and pro tokens are marked as buttons.
10. Version 0.4.N (build.gradle.kts), RELEASE_NOTES.md updated.
Deliberately NOT changed (be honest with the owner): the app stays portrait-locked (screen rotation not supported by design), presets still in memory only (Stage 5), no real-device battery/memory profiling or instrumented tests were possible, TalkBack was not fully audited, errors caused by another app taking the camera are not observed yet, release title in the workflow still says 0.2.N.
